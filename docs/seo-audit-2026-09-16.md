# DSH Hub SEO 优化与验证

核查日期：2026-09-16。基于当前源码、真实目录快照和本地生成页面；尚未提交或部署，未读取站长平台排名与收录报表。

## 详情描述

详情正文、meta description、Open Graph、Twitter 和 SoftwareApplication description 均使用“原描述 + AI 分析”。如果分析已经包含在原描述中则不重复追加；没有原描述时回退到 README 摘要，没有分析时保留原描述。删除单独的 AI 分析块，避免同一段内容重复展示。

不再按原来的 160 字符硬截断元描述，确保合并文本进入 HTML。搜索引擎仍可能按查询重新选择或截断摘要，页面不能强制它展示完整文本。语言回退沿用现有策略：繁体描述借用简体内容，缺少本地化 AI 分析时回退简体。

## 独立分类与分页

- 11 个分类，每个分类有五语名称、具体用途介绍、静态插件列表。
- URL 示例：`/zh-CN/categories/memory/`、`/zh-CN/categories/memory/page/2/`。
- 总目录分页：`/zh-CN/page/2/`；第一页使用 `/zh-CN/`。
- 首页分类入口和详情分类标签直接链接落地页；分页使用真实链接，每页独立 canonical、hreflang 与站点地图记录。
- 切换语言保留当前分类和页码。每页 24 条，所有列表在构建时写入 HTML，无需 JavaScript 即可浏览分类与分页。
- 当前每种语言有 1,588 个列表路径，其中包含 11 个分类及其分页、总目录及其分页；五语共 7,940 个列表页面。
- 搜索、组合筛选和自定义排序继续使用主页查询参数，不把任意查询组合扩展成索引页面。

## 同名与副本治理

原始快照 14,253 条记录中有 43 条重复 URL 记录；核对后这 43 组的内容完全相同。保留 14,210 个唯一详情 URL。

唯一详情中存在 1,043 组同名包。同名不是 fork 证据，现有快照也没有可靠的 GitHub parent/source 元数据，因此不会把它们统一标成 fork、删除或 noindex。

- 同名详情标题补充仓库标识，并展示最多 6 个同名包的其他仓库链接。
- 仅在包名、版本、40 位提交 SHA、包路径、足够长的 README、原描述、安装说明、依赖、分类、兼容记录和许可证均一致时，认定为内容副本。
- 副本组选择确定性的目录代表页；该选择不表示判定了上游作者。代表页自引用 canonical，副本 canonical 和语言 alternate 指向代表页。
- 副本 URL 继续提供自己的详情和仓库链接，页面提示代表页位置。默认目录、相关推荐、网站搜索索引和 sitemap 仅保留代表条目。
- 本次只有 8 组满足规则，网站目录因此保留 14,202 条代表条目。不同版本、不同内容和仅仅同名的项目仍保留独立页面。
- `.catalog/seo-governance.report.json` 在每次构建时生成完整判定报告。源目录快照不被改写。

## 搜索加载优化

公共客户端的 `index.json` 保持原格式和完整目录，兼容既有 CLI/SDK；新增只供网站使用的 `browser-en.json` 和 `browser-zh.json`，通过 manifest 的可选字段发现。

网站索引使用紧凑行格式，去掉重复字段名、重复包名和已可从显示字段恢复的搜索词。只包含对应语言的展示描述，仍保留中英文检索能力、排序数据和原安装命令。

首页、分类页和静态分页不请求搜索索引。提交搜索或使用动态筛选/排序后才加载一个语言索引；同一页面复用请求。请求失败可重试，旧页面遇到版本资源 404 时刷新 manifest 后重试一次。
